贪心：为什么可以在最早合法处切分

围绕划分字母区间，推导字符最后位置形成的必要边界，说明当前切分为何安全，并对照原始代码讨论重复扫描的成本。

划分字母区间的边界如何闭合

查看图示的文字结构
flowchart TD
 Q{"还有未扫描的字符？"} -->|否| Z["返回所有片段长度"]
 Q -->|是| A["扫描下一个位置 i"]
 A --> B["end = max(end, 当前字符最后位置)"]
 B --> C{"i 已到达 end？"}
 C -->|否| Q
 C -->|是| D["记录当前片段长度"]
 D --> E["下一个片段从 i+1 开始"]
 E --> Q

片段中的每个字符都必须留在片段内，因此最远的最后出现位置是必要边界。扫描达到它时，立即切分不会给后续片段增加限制。

先识别问题的结构

题目存在可以逐步做出的局部选择，并且能证明“先做这个选择，后面仍可得到最优解”时，才考虑贪心。通常通过交换论证、不可突破的边界或不变量证明；仅仅要求最大／最小值并不足以判断是贪心。

划分字母区间中，片段必须包含其中每个字符的最后出现位置，因此切点不能早于这些位置的最大值。扫描到这个最早合法切点就切开，不会限制后续片段，而且能保留最多切分机会。

核心思路

贪心算法每一步选择当前最有利的方案。关键不是“看起来合理”，而是证明当前选择不会损害后续最优解；常见形式是维护当前区间必须延伸到的最远边界。

做题步骤与教学骨架

先定义局部选择，再证明其安全性，最后确定要维护的状态。贪心没有覆盖所有题目的固定代码，下面只对应“维护最远必要边界、到最早合法位置就切分”的模式：

求出每个元素要求覆盖到的位置（本题是字符最后出现的位置）
start = 0，end = 0
for 位置 i 从左到右:
    end = max(end, 当前元素要求覆盖到的位置)
    if i == end:
        记录区间 [start, end]
        start = i + 1

复习时检查两件事：为什么 end 之前不能切，以及为什么到 end 立即切不会让结果变差。

例题：划分字母区间

题目链接：LeetCode 763. 划分字母区间

class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        if len(s) == 1: return [1]
        l, max_r = 0, -1
        ans = []
        for i, ch in enumerate(s):
            cur_r = i # 防止根本就没有重复导致的一路走到尾！！！！
            for j in range(i+1, len(s)):
                if s[j] == ch:
                    cur_r = j
            max_r = max(max_r, cur_r) # 每次找到当前最右并更新直到相遇就说明是一个串了
            if i == max_r: # 已经找完
                ans.append(max_r - l + 1)
                l = i + 1
                
        return ans

实现细节：扫描当前片段内的字符，并把 max_r 扩展到这些字符最后出现的位置。当 i == max_r 时，当前片段中的所有字符都不会在后面再次出现，可以立即切分。

本文代码每次向后寻找字符最后位置，最坏为 O(n²)；若先用哈希表记录每个字符最后出现的位置，相同贪心逻辑可降为 O(n)。

并查集：集合代表与路径压缩

从省份数量、冗余连接、等式约束和账户合并理解集合归属，重点澄清直接父节点与当前根节点，以及正确统计集合的方法。

W韦君豪约 8 分钟

只把集合代表连接起来

查看图示的文字结构
flowchart LR
 A["查询元素 a、b"] --> B["find(a)、find(b)"]
 B --> C{"根相同？"}
 C -->|是| D["已经连通，无需合并"]
 C -->|否| E["连接两个不同的根"]
 B --> F["查找时压缩路径"]

集合由根节点代表。路径压缩只缩短查找路径，不改变集合关系；本文采用直接连接两个根；按大小或秩合并是可以另行加入的优化，用于避免树长期偏向一条链。

先识别问题的结构

  • 只关心是否同组、共有几组：关系具有传递性，例如城市间接连通、变量相等、账户共享邮箱。
  • 不断合并集合，随后查询归属：合并后不会拆开，适合用根节点代表一个集合。
  • 无向图加边判环：若一条边的两个端点原本已经连通，再连这条边就会成环。

先判断“谁是节点、什么关系允许合并”。普通并查集不直接解决最短路径、有向图可达性或删除边后的分裂；静态连通分量也可以用 DFS/BFS。

状态设计与核心骨架

  1. 给节点编号，每个节点最初独立成组，父节点是自己。
  2. find(x) 沿父指针找到根；下面的写法还会进行路径压缩。
  3. union(x, y) 先找两个根；不同根才合并，相同根则返回 False。
  4. 按题意统计成功合并次数、比较根，或按根分组。

核心实现如下；26 对应小写字母，其他题改成实际节点数（若编号从 1 开始，注意预留下标）：

parents = [i for i in range(26)]
def find(x):
    if parents[x] != x:
        parents[x] = find(parents[x])
    return parents[x]
def union(x, y):
    px, py = find(x), find(y)
    if px == py: return False
    parents[py] = px
    return True

parents[x] 是 直接父节点；find(x) 返回 当前根节点（集合代表）；根满足 parents[root] == root。合并时挂接的是两个根，方向可选，根的编号不一定最小，也不一定是最早出现的节点。

重点：为什么不能直接用 len(set(parents))

并查集始终用整条父指针链表示归属，合并完成后，同组节点的直接父节点不一定相同。因此，问题不在于“还没真正合并”，而在于把直接父节点误当成集合代表。

union 只修改一个根的父指针，不会遍历它的全部后代。find(x) 才会沿途找到当前根，并把本次访问路径上的节点直接挂到根下；它不会一次更新整个集合。即便一个节点之前压缩过，后续根再次被合并后，也可能需要重新 find。

用与本文的 547 双层循环一致的处理顺序举例：

操作 parents 说明
初始化 [0, 1, 2, 3] 四个集合
union(0, 3) [0, 1, 2, 0] 3 挂到 0
union(1, 2) [0, 1, 1, 0] 2 挂到 1
union(2, 3) [1, 1, 1, 0] 根 0 挂到根 1，但 3 仍直接指向 0
find(3) [1, 1, 1, 1] 沿 3 → 0 → 1 查根并压缩

第三次合并后，四个节点已经连通，但 set(parents) == {0, 1}，会错算成两个省份。

正确计数有三种写法（这里节点为 0..n-1）：

# 方式一：对每个节点查当前根，再去重
count = len({find(i) for i in range(n)})

# 方式二：直接数根；不需要先压缩所有节点
count = sum(parents[i] == i for i in range(n))

# 方式三：初始化 count = n，每次 union 返回 True 时 count -= 1
# 见下面 547 的当前代码。

若想继续使用 len(set(parents))，必须在所有合并结束后对每个节点调用 find，且统计前不再合并。查询两点是否同组也应比较 find(x) == find(y)，不要比较 parents[x] == parents[y]。

例题一：547. 省份数量

题目链接：LeetCode 547. 省份数量

我的代码

class Solution:
    def findCircleNum(self, isConnected: List[List[int]]) -> int:
        """
        并查集的经典骨架：
            parent = list(range(n))

            def find(x): # 一直往上找到parent是自己的节点！
                if parent[x] != x:
                    parent[x] = find(parent[x])
                return parent[x]

            def union(a, b): # 
                ra = find(a)
                rb = find(b)

                if ra == rb:
                    return False

                parent[rb] = ra
                return True
        """
        n = len(isConnected)
        provinces = n
        parents = [i for i in range(n)] # 记录各自的parent；初始化为自己

        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]

        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True

        for i in range(n):
            for j in range(i + 1, n):
                if isConnected[i][j] == 1:
                    if union(i, j):
                        provinces -= 1
        
        return provinces

对应思路：城市是节点，矩阵中的 1 是合并依据。对称矩阵只扫描上三角即可。每次真正合并两个集合，provinces 减一；已连通的两点不会重复扣减，所以不需要最后统一压缩再计数。

可复现上面陷阱的输入为 [[1,0,0,1],[0,1,1,0],[0,1,1,1],[1,0,1,1]]：实际只有一个省份，当前计数写法返回 1，合并后直接对父数组去重却得到 2。

例题二：684. 冗余连接

题目链接：LeetCode 684. 冗余连接

我的代码

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        # 逻辑就是找到环，然后把成环的最后一条边删了吧？
        # 模拟一遍发现其实就是已经union的东西！
        parents = [i for i in range(len(edges) + 1)] # 从1开始！

        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = parents[px]
            return True

        for i, j in edges:
            if not union(i, j):
                return [i, j]

对应思路：按输入顺序加入无向边。union(i, j) 返回 False 时，两点已经有路径相连，这条边恰好闭合环。题目保证“树加一条边”，因此这就是唯一环中最后出现的边，满足返回顺序要求。

例如 [[1,2],[1,3],[2,3]]：前两条合并成功，第三条两端已经同组，返回 [2,3]。px 已是根，所以代码中的 parents[px] 等于 px。

例题三：990. 等式方程的可满足性

题目链接：LeetCode 990. 等式方程的可满足性

我的代码

class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        # 等于则连上，不等于则不连。判断所有不等的find是否到同一节点
        parents = [i for i in range(26)]
        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True

        non_equations = []
        for eq in equations:
            x, y = eq[0], eq[3]
            if eq[1] == '=':
                union(ord(x)-ord('a'), ord(y)-ord('a'))
            else:
                non_equations.append([x, y])
        
        for x, y in non_equations:
            if find(ord(x)-ord('a')) == find(ord(y)-ord('a')):
                return False
        return True

对应思路：字母是节点，先合并所有等式，再检查不等式两端是否同根。!= 不能用来合并，因为“不等”没有传递性。

必须等所有等式处理完才检查：例如 ["a!=c", "a==b", "b==c"]，第一条暂时看不冲突，但后两条把 a,b,c 合到同组，最终应返回 False。

例题四：721. 账户合并

题目链接：LeetCode 721. 账户合并

我的代码

from collections import defaultdict

class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        """
        思路：用set(a) & set(b) 非空则是同一个用户，直接union。 - 复杂度很高！
        """
        parents = [i for i in range(len(accounts))] # 每个人名对应在列表的index
        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True
        """
        更好的思路：直接遍历邮箱，第一次出现就放在当前index，不是则进行名字的union！
        """
        email_2_account = {}

        for i in range(len(parents)):
            for email in accounts[i][1:]:
                if email in email_2_account: # 之前出现过，说明这个account属于之前的人
                    union(i, email_2_account[email])
                else:
                    email_2_account[email] = i

        groups = defaultdict(list)
        for email, account_idx in email_2_account.items():
            root = find(account_idx) # 需要找到最开始的user名合并在这里不然合并零散！
            groups[root].append(email)

        ans = []
        for root, emails in groups.items():
            name = accounts[root][0]
            ans.append([name] + sorted(emails))
        return ans

对应思路：这份实现以“账户下标”为节点，共同邮箱才是合并证据，同名本身不够。email_2_account 记录邮箱第一次出现的账户；再次出现时合并两个账户，避免账户两两比较。全部合并后，再按 find(account_idx) 聚合邮箱并排序。

例如账户 A 有邮箱 x,y，B 有 z，C 有 y,z：C 会把前两组连接成同一组。映射里保存的仍是最初账户下标，所以分组时必须重新查根。

原注释中的“最开始的 user”应理解成当前集合代表，并不保证是最早的账户；同一人的账户名称一致，故 accounts[root][0] 可以取名称。最初的集合交集思路也应只比较邮箱 accounts[i][1:]，不能把名字算作共同证据。

复习检查点

  • 合并两个根；同根时不改集合数。
  • 查归属、判同组、分组用 find；数根可直接判断 parents[i] == i。
  • find 的路径压缩只更新访问路径，后续合并仍可能改变代表。
  • 这份简洁模板只有路径压缩，没有按秩/大小合并；不要直接套用“两种优化同时使用时”的近似常数摊还复杂度结论。未压缩的长链上，单次递归查根仍可能走过很多节点。

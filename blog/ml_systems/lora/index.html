LoRA：低秩更新、量化底座与自适应预算

完整推导低秩适配的更新与初始化，比较目标模块、QLoRA 和 AdaLoRA，并讨论合并部署、多适配器与显存节省的边界。

W韦君豪约 8 分钟

参数高效微调将任务适配限制在较小的可训练空间中，减少梯度、优化器状态和任务权重的保存成本。LoRA、QLoRA 与 AdaLoRA 分别关注低秩更新、底座量化和秩预算分配。它们节省的资源不同，也都需要结合激活显存、目标模块和最终任务表现判断收益。

底座和低秩分支共同产生输出，但参数更新只作用于适配器。冻结底座不等于取消经过底座的前向与反向计算，尤其不意味着激活显存自动消失。

把增量限制为低秩矩阵

LoRA 冻结底座权重 (W)，把任务相关更新限制为低秩矩阵：

W′=W+ΔW,ΔW=αrBAW'=W+\Delta W, \qquad \Delta W=\frac{\alpha}{r}BAW′=W+ΔW,ΔW=rα​BA

其中 A∈Rr×dinA\in\mathbb R^{r\times d_{in}}A∈Rr×din​、B∈Rdout×rB\in\mathbb R^{d_{out}\times r}B∈Rdout​×r，且 r≪din,doutr\ll d_{in},d_{out}r≪din​,dout​。训练只更新 A/B，因此显著减少梯度、优化器状态和可训练参数存储。

从零增量开始的初始化

原始 LoRA 对 AAA 使用随机高斯初始化、令 B=0B=0B=0。因此训练开始时：

ΔW0=αrB0A0=0,h0=(W+ΔW0)x=Wx.\Delta W_0=\frac{\alpha}{r}B_0A_0=0, \qquad h_0=(W+\Delta W_0)x=Wx.ΔW0​=rα​B0​A0​=0,h0​=(W+ΔW0​)x=Wx.

也就是说，刚插入 LoRA 时模型输出与原预训练模型完全相同，不会因为随机 Adapter 立即扰动已有能力；但随机的 A0A_0A0​ 已经提供了可供 BBB 学习的非零方向。

令上游梯度为 g=∂L/∂hg=\partial\mathcal L/\partial hg=∂L/∂h，忽略 Batch 维后有：

∂L∂B=αrg(Ax)⊤,∂L∂A=αrB⊤gx⊤.\frac{\partial\mathcal L}{\partial B} =\frac{\alpha}{r}g(Ax)^\top, \qquad \frac{\partial\mathcal L}{\partial A} =\frac{\alpha}{r}B^\top gx^\top.∂B∂L​=rα​g(Ax)⊤,∂A∂L​=rα​B⊤gx⊤.

当 A0A_0A0​ 随机而 B0=0B_0=0B0​=0 时，第一步通常是 BBB 获得非零梯度，AAA 的梯度暂时为零；待 BBB 离开零点后，两者都能继续训练。如果 A0=B0=0A_0=B_0=0A0​=B0​=0，则 Ax=0Ax=0Ax=0 且 B=0B=0B=0，两边梯度同时为零，LoRA 分支会卡在零点，无法启动学习。

一句话记忆：

一个随机、一个为零：既让初始模型严格不变，又保留可学习梯度；两个都为零：初始模型虽不变，但 LoRA 也完全“调不动”。

不同框架可能把 AAA 实现为 Kaiming/Uniform 等随机初始化；关键条件不是必须使用某一种高斯分布，而是初始乘积 BA=0BA=0BA=0，同时不能让两个因子都失去梯度通路。

目标模块决定可调整的行为

LoRA 可以挂在任意线性权重上，常见选择是：

Target module 作用直觉 适用情况
q_proj、v_proj Q 改变“关注谁”，V 改变“取回什么内容” 原始 LoRA/常见轻量配置，参数最省
q_proj、k_proj、v_proj、o_proj 同时调整 Attention 的匹配、内容与输出混合 希望更完整地适配 Attention
MLP 的 gate_proj、up_proj、down_proj 调整逐 token 的非线性特征变换 领域迁移、知识/能力适配，或追求更接近全参微调
Embedding、lm_head 调整输入词表示或输出词分布 新增 Token、词表或输出层确实需要变化时

预算有限时通常先试 q_proj、v_proj，或覆盖全部 Attention 投影；质量优先时常采用 QLoRA 风格的 all-linear，把 Attention 与 MLP 中的线性层都覆盖。范围越大，可训练参数、优化器状态和 Adapter 文件也越大，应通过任务验证选择。

不要把理由说成“Attention 存知识更多”。更合适的直觉是：Attention 负责根据当前上下文路由和混合信息，MLP/FFN 负责逐 token 的非线性特征变换，也有研究将 FFN 解释为 Key-Value Memory。模型知识是分布式的，并不只存在某一个模块。Attention-only LoRA 常见，主要因为它以较少参数就能有效改变信息交互方式；需要更强领域适配时，加入 MLP 往往更有容量。

一句话选择：

小预算先改 Attention；追求效果或领域变化较大时改 all-linear；涉及新词表时再考虑 Embedding/lm_head。

QLoRA：量化底座上的高精度适配器

QLoRA 可以理解为“4-bit 量化底座 + LoRA 微调”：底座权重被量化保存并保持冻结，LoRA 的 A/BA/BA/B 通常仍以 BF16/FP16 等较高精度训练。其前向过程可简写为：

h=Dequant⁡(W4bit)x+αrBAx.h=\operatorname{Dequant}(W_{4\mathrm{bit}})x +\frac{\alpha}{r}BAx.h=Dequant(W4bit​)x+rα​BAx.

计算时，量化权重会按块反量化到计算 dtype 参与矩阵乘法；梯度可以穿过这条计算路径传给 LoRA，但不会更新冻结的 4-bit 底座。因此 QLoRA 不是“用 4-bit 梯度训练全部模型”，也不是“把 LoRA 参数本身量化为 4-bit”。

原始 QLoRA 的三个关键点是：

  • NF4：为近似正态分布的预训练权重设计的 4-bit 数据类型，通常比简单均匀 INT4 更适合权重量化；
  • Double Quantization：进一步量化量化过程中的 scale/constant，继续减少元数据显存；
  • Paged Optimizer：利用分页/统一内存缓解长序列训练中的瞬时显存峰值，降低 OOM 风险。
对比项 LoRA QLoRA
冻结底座的常见存储精度 FP16/BF16 4-bit，常见 NF4
真正训练的参数 LoRA A/B LoRA A/B
主要额外收益 减少梯度和优化器状态 在 LoRA 基础上进一步压缩底座权重
不能自动省掉 激活、前后向计算 激活、前后向计算及反量化开销

QLoRA 常采用 all-linear，但二者不是同一个概念：QLoRA 的定义重点是“量化冻结底座后训练 LoRA”，all-linear 只是常见 Target Module 策略。部署时可以保留“量化底座 + Adapter”，也可以反量化后合并并重新量化；后者可能引入额外量化误差。

一句话记忆：

LoRA 省的是可训练参数、梯度和优化器状态；QLoRA 再把最大块的冻结底座权重从 16-bit 压到 4-bit，但激活显存并不会自动消失。

AdaLoRA：在全局预算内分配低秩方向

标准 LoRA 通常给所有 Target Matrix 分配相同 Rank rrr，但不同层、不同模块对当前任务的重要性并不相同。AdaLoRA 在一个全局参数预算下动态分配 Rank：重要矩阵保留更多低秩方向，不重要矩阵被剪到更低 Rank。

AdaLoRA 将增量写成 SVD-like 形式：

ΔW=PΛQ⊤,Λ=diag⁡(λ1,…,λr).\Delta W=P\Lambda Q^\top, \qquad \Lambda=\operatorname{diag}(\lambda_1,\ldots,\lambda_r).ΔW=PΛQ⊤,Λ=diag(λ1​,…,λr​).

每个 (pi,λi,qi)(p_i,\lambda_i,q_i)(pi​,λi​,qi​) 构成一个 Rank-1 Triplet。训练初期使用较高的 init_r 探索候选方向；随后根据参数及其梯度估计重要性，周期性把低重要度的 λi\lambda_iλi​ Mask/Prune 掉，逐步收缩到 target_r 对应的总预算；最后固定 Rank 分配继续微调。正交正则用于减少不同方向的冗余，使 SVD-like 分解更稳定。

方法 主要解决的问题
LoRA 用固定低 Rank 表示权重增量
QLoRA 用 4-bit 压缩冻结底座权重
AdaLoRA 在相同低秩预算下，自适应决定各矩阵应分到多少 Rank

AdaLoRA 的优势是在预算很紧时减少“一刀切 Rank”造成的浪费；代价是需要跟踪重要性、维护剪枝日程和正交正则，对 init_r、target_r、Warmup、Pruning Interval 与总训练步数更敏感。它与 QLoRA 解决的是不同维度的问题，概念上可以组合，但要确认具体训练框架是否支持相应量化、裁剪和保存流程。

一句话记忆：

LoRA 是“每个目标矩阵发同样的 Rank 预算”；AdaLoRA 是“先多发一些，再根据训练中的重要性动态回收并重新分配”。

训练与部署中的资源收益

  • 降低训练显存，尤其是 Adam 一阶/二阶状态；
  • Adapter 文件小，便于多任务保存和切换；
  • 可以在部署前将 ΔW merge 回主权重，避免额外推理层；
  • 也可以不 merge，通过 Adapter Serving 动态切换租户/任务。

参数、激活与行为的边界

  • 底座参数虽然冻结，前向和反向传播仍需经过底座网络；
  • 激活显存并不会因为可训练参数少而自动消失；
  • Rank 太低可能容量不足，太高则收益递减；
  • Target module、α、Dropout、初始化与数据量都会影响效果；
  • 多 Adapter 并发 serving 需要处理权重调度、Batch 合并和缓存；
  • LoRA 限制了参数更新空间，但不自动保证没有领域过拟合或行为遗忘。

MoE：用稀疏路由扩大模型容量

解释 Top-k 路由、负载均衡、专家容量与通信，区分总参数、激活参数和实际运行成本。

W韦君豪约 7 分钟

Mixture of Experts 把一部分共享计算改成按输入选择的专家计算。对于语言模型，常见做法是在 Transformer 的某些层，用多个前馈网络替代单个 FFN，再让 Router 为每个 token 选择少量专家。模型因此可以保存更多参数，同时把单个 token 的计算限制在一部分参数上。

这里的“专家”是一个独立参数化的子网络。它不天然对应医学、数学或编程等人类划定的领域；分工来自训练中的路由选择与参数更新，可能围绕词法、语法、表示模式或其他统计结构形成。

从稠密 FFN 到稀疏计算

设某个 token 的输入表示为 xxx，共有 EEE 个专家 EiE_iEi​。Router 输出 logits g(x)g(x)g(x)，经 Softmax 得到路由概率，再选出 Top-kkk：

S(x)=TopK⁡(g(x)),y=∑i∈S(x)pi(x)Ei(x).S(x)=\operatorname{TopK}(g(x)), \qquad y=\sum_{i\in S(x)}p_i(x)E_i(x).S(x)=TopK(g(x)),y=i∈S(x)∑​pi​(x)Ei​(x).

不同实现对 pip_ipi​ 的定义不完全相同：它可以保留原 Softmax 概率，也可以在被选中的专家中重新归一化。这个差别会影响输出尺度和 Router 梯度，复现模型时应保持一致。

图中把“决定送往哪里”和“执行专家计算”分开了。不同 token 可以选择不同的专家组合；合并阶段必须恢复原始 token 顺序，并累加同一个 token 在多个专家上的加权输出。其他 Transformer 部分，例如 Attention、归一化和输出层，通常仍由所有 token 共享。

假设四个专家的路由概率为 (0.60,0.25,0.10,0.05)(0.60,0.25,0.10,0.05)(0.60,0.25,0.10,0.05)，Top-2 选择前两个专家。如果实现采用选中专家内重新归一化，最终权重约为 (0.706,0.294)(0.706,0.294)(0.706,0.294)；未选中的两个专家不为该 token 执行 FFN。这个例子只说明一次路由，不能由概率大小判断专家具有什么稳定语义。

Top-1 与 Top-2 的不同代价

Top-1 每个 token 只进入一个专家，减少专家计算和通信，也简化容量安排。Switch Transformer 展示了这种简化路由能够用于大规模稀疏模型。Switch Transformers

Top-2 同时组合两个专家，给 token 提供更丰富的计算路径，但专家侧 FLOPs、分发数据量和合并操作通常更多。它也不会自动解决负载不均衡：如果许多 token 都选择同一对专家，热点仍然存在。Top-kkk 的选择需要同时考虑学习效果、路由稳定性和真实硬件上的吞吐。

Top-kkk 集合的选择本身是离散的。常见方案让选中专家的连续路由权重参与梯度计算，再结合负载均衡目标训练 Router。不能把离散选择简单理解成普通 Softmax 上所有专家都得到同样完整的梯度。

总参数、激活参数与显存分别表示什么

设共享部分有 PsP_sPs​ 个参数，每个专家有 PeP_ePe​ 个参数，共有 EEE 个专家，每个 token 激活 kkk 个。忽略 Router 和各层差异时：

Ptotal≈Ps+EPe,Pactive/token≈Ps+kPe.P_{\mathrm{total}}\approx P_s+EP_e, \qquad P_{\mathrm{active/token}}\approx P_s+kP_e.Ptotal​≈Ps​+EPe​,Pactive/token​≈Ps​+kPe​.

例如 Ps=2P_s=2Ps​=2、Pe=1P_e=1Pe​=1、E=8E=8E=8、k=2k=2k=2，以十亿参数为单位，则总参数约为 100 亿，每 token 激活约为 40 亿。它有更多可分配的参数容量，却不能据此声称只需容纳 40 亿参数的权重。

所有专家权重仍然需要保存在某些设备或存储层中。训练时还要考虑梯度与优化器状态，推理时还要考虑 KV Cache、激活、路由缓冲区和批量大小。把专家分散到多张设备可以摊开权重存储，但会引入跨设备通信；将专家按需加载到设备则可能受到带宽与加载延迟限制。

一个 batch 中不同 token 可以覆盖全部专家，所以“每 token 只激活少量参数”不等于“一次 batch 只读取少量专家”。稠密模型和 MoE 的比较至少需要同时报告总参数、激活参数、计算量、内存占用和实际延迟。

负载不均衡为何会破坏收益

若 Router 早期偏向少数专家，这些专家会收到更多 token 和梯度，其余专家难以获得足够训练，进一步加剧选择失衡。即使平均每个专家的 token 数不多，最繁忙的专家也可能拖慢整个层，因为合并输出通常需要等待分发任务完成。

Switch 使用的 Top-1 负载均衡辅助项可以写成：

Lbalance=αE∑i=1EfiPi,\mathcal L_{\mathrm{balance}} =\alpha E\sum_{i=1}^{E}f_iP_i,Lbalance​=αEi=1∑E​fi​Pi​,

其中，一个路由批次包含 TTT 个 token：

fi=1T∑x1{argmax⁡g(x)=i},Pi=1T∑xpi(x).f_i=\frac{1}{T}\sum_{x}\mathbf1\{\operatorname{argmax}g(x)=i\}, \qquad P_i=\frac{1}{T}\sum_x p_i(x).fi​=T1​x∑​1{argmaxg(x)=i},Pi​=T1​x∑​pi​(x).

fif_ifi​ 表示实际进入专家 iii 的比例，PiP_iPi​ 表示 Router 分配给它的平均概率。辅助项鼓励概率质量不要继续集中到已经接收过多 token 的专家，主任务损失则负责学习有用的表示。它是一种平衡质量与负载的训练设计，并不意味着每个 token 都应均匀使用所有专家。系数过大可能压过任务目标，过小又可能无法缓解热点。

容量限制、Token 溢出与通信

为了方便并行实现，一些方案为专家设置固定容量。Top-1 情况下，常用近似为：

capacity≈⌈capacity factor⋅TE⌉.\mathrm{capacity}\approx \left\lceil\mathrm{capacity\ factor}\cdot\frac{T}{E}\right\rceil.capacity≈⌈capacity factor⋅ET​⌉.

提高 capacity factor 留出更多余量，可以减少溢出，却增加缓冲区和可能的空槽计算。Top-kkk 方案还要计入总分发次数，具体容量定义由实现决定。专家超过容量后，有的方案跳过该 token 的专家变换并保留残差路径，有的转发或重新分配；也存在动态容量或不丢弃 token 的实现，不能将某一种溢出策略当作 MoE 的固有性质。

Expert Parallel 通常先按专家把 token 分组，再通过 All-to-All 把表示发送到拥有专家的设备，计算后再送回。小 batch 可能让每个专家只收到很少的 token，矩阵乘法利用率下降；大 batch 能摊薄开销，却可能提高等待时间和内存需求。因此线上成本受并行拓扑、带宽、路由分布和服务延迟目标共同影响。

如何判断稀疏化是否有效

MoE 的价值需要在可比较的预算下检验。固定训练 FLOPs，可以观察更多总参数是否带来质量收益；固定质量目标，可以比较训练成本；固定硬件与服务负载，则应看吞吐、首 token 延迟和长尾延迟。不同问题对应不同结论，不能只展示总参数规模来代替评测。

训练阶段还应记录各专家的 token 比例、溢出率和梯度情况。推理阶段需要测量专家通信占比，以及不同提示和长度是否形成热点。某个负载均衡损失在单次实验中改善了结果，仍不足以证明它在所有规模上有效；只改变该因素、使用相同数据和预算进行对照，才能更清楚地识别收益与代价。

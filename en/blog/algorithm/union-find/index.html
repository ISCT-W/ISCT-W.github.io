Union-Find: representatives are not immediate parents

## Connect only the representatives

WJunhao WeiAbout 8 min read

Connect only the representatives

View diagram structure (original)
flowchart LR

 B --> C{"根相同？"}
 C -->|是| D["已经连通，无需合并"]
 C -->|否| E["连接两个不同的根"]
 B --> F["查找时压缩路径"]

A root represents a set. Path compression shortens lookup paths without changing membership. The examples attach one root directly to another; union by size or rank is a separate optimization that can prevent persistently chain-shaped trees.

Recognize the structure first

  • Only group membership or group count matters: The relation is transitive, as with indirect city connections, equal variables, or accounts sharing an email.
  • Sets merge and membership is queried afterward: Sets do not split, making a root a useful representative.
  • Adding undirected edges to detect a cycle: An edge whose endpoints are already connected closes a cycle.

Identify the nodes and the evidence that permits a union. Ordinary Union-Find does not directly solve shortest paths, directed reachability, or splits after edge deletion. Static connected components can also be found with DFS or BFS.

State design and core skeleton

  1. Number the nodes. Initially each is its own set and parent.
  2. find(x) follows parent pointers to the root; the implementation also compresses the path.
  3. union(x, y) first finds both roots. Merge only different roots; return False for identical roots.
  4. Count successful merges, compare roots, or group by roots as required.

Here 26 represents lowercase letters. Other problems require the actual node count; reserve an extra index for one-based labels.

parents = [i for i in range(26)]
def find(x):
    if parents[x] != x:
        parents[x] = find(parents[x])
    return parents[x]
def union(x, y):
    px, py = find(x), find(y)
    if px == py: return False
    parents[py] = px
    return True

parents[x] is the immediate parent; find(x) returns the current root or representative. A root satisfies parents[root] == root. Unions connect roots, in either direction; the representative need not have the smallest index or be the earliest node.

Why len(set(parents)) is not generally correct

Membership is represented by the entire parent chain. Nodes in an already merged set need not share an immediate parent. The mistake is treating an immediate parent as the representative, not assuming that the merge somehow remains unfinished.

union changes one root’s parent without visiting all descendants. find(x) follows and compresses only the path it visits, not the whole set. Even a previously compressed node may need another find after its root participates in a later union.

The following order matches the double loop in the Number of Provinces example:

Operation parents Meaning
Initialize [0, 1, 2, 3] Four sets
union(0, 3) [0, 1, 2, 0] Attach 3 to 0
union(1, 2) [0, 1, 1, 0] Attach 2 to 1
union(2, 3) [1, 1, 1, 0] Attach root 0 to root 1; 3 still points directly to 0
find(3) [1, 1, 1, 1] Follow and compress 3 → 0 → 1

After the third merge all four nodes are connected, yet set(parents) == {0, 1} incorrectly suggests two provinces.

There are three correct counting approaches for nodes 0..n-1:

# 方式一：对每个节点查当前根，再去重
count = len({find(i) for i in range(n)})

# 方式二：直接数根；不需要先压缩所有节点
count = sum(parents[i] == i for i in range(n))

# 方式三：初始化 count = n，每次 union 返回 True 时 count -= 1
# 见下面 547 的当前代码。

To use len(set(parents)), call find on every node after all unions and perform no further unions before counting. Likewise, compare find(x) == find(y) for membership, not parents[x] == parents[y].

Example 1: Number of Provinces

Problem: LeetCode 547

My code

class Solution:
    def findCircleNum(self, isConnected: List[List[int]]) -> int:
        """
        并查集的经典骨架：
            parent = list(range(n))

            def find(x): # 一直往上找到parent是自己的节点！
                if parent[x] != x:
                    parent[x] = find(parent[x])
                return parent[x]

            def union(a, b): # 
                ra = find(a)
                rb = find(b)

                if ra == rb:
                    return False

                parent[rb] = ra
                return True
        """
        n = len(isConnected)
        provinces = n
        parents = [i for i in range(n)] # 记录各自的parent；初始化为自己

        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]

        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True

        for i in range(n):
            for j in range(i + 1, n):
                if isConnected[i][j] == 1:
                    if union(i, j):
                        provinces -= 1
        
        return provinces

Reasoning: Cities are nodes; matrix entries of 1 provide union evidence. Scan only the upper triangle of the symmetric matrix. Decrease provinces only when two distinct sets actually merge. Already-connected nodes do not decrement it again, so final global compression is unnecessary for this count.

The pitfall is reproducible with [[1,0,0,1],[0,1,1,0],[0,1,1,1],[1,0,1,1]]: there is one province, and the running count returns 1; deduplicating the final parent array gives 2.

Example 2: Redundant Connection

Problem: LeetCode 684

My code

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        # 逻辑就是找到环，然后把成环的最后一条边删了吧？
        # 模拟一遍发现其实就是已经union的东西！
        parents = [i for i in range(len(edges) + 1)] # 从1开始！

        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = parents[px]
            return True

        for i, j in edges:
            if not union(i, j):
                return [i, j]

Reasoning: Add undirected edges in input order. If union(i, j) returns False, the endpoints already share a path and this edge closes the cycle. Under the problem’s “tree plus one edge” assumption, this is the final input edge on the unique cycle, as requested.

For [[1,2],[1,3],[2,3]], the first two unions succeed and the third returns [2,3]. Since px is already a root, parents[px] equals px.

Example 3: Satisfiability of Equality Equations

Problem: LeetCode 990

My code

class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        # 等于则连上，不等于则不连。判断所有不等的find是否到同一节点
        parents = [i for i in range(26)]
        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True

        non_equations = []
        for eq in equations:
            x, y = eq[0], eq[3]
            if eq[1] == '=':
                union(ord(x)-ord('a'), ord(y)-ord('a'))
            else:
                non_equations.append([x, y])
        
        for x, y in non_equations:
            if find(ord(x)-ord('a')) == find(ord(y)-ord('a')):
                return False
        return True

Reasoning: Letters are nodes. First merge every equality, then check whether an inequality’s endpoints have the same root. Inequality is not transitive and cannot be used for merging.

Finish all equalities before checking inequalities. In ["a!=c", "a==b", "b==c"], the first constraint initially appears consistent, but the next two connect a,b,c, so the final result must be False.

Example 4: Accounts Merge

Problem: LeetCode 721

My code

from collections import defaultdict

class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        """
        思路：用set(a) & set(b) 非空则是同一个用户，直接union。 - 复杂度很高！
        """
        parents = [i for i in range(len(accounts))] # 每个人名对应在列表的index
        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True
        """
        更好的思路：直接遍历邮箱，第一次出现就放在当前index，不是则进行名字的union！
        """
        email_2_account = {}

        for i in range(len(parents)):
            for email in accounts[i][1:]:
                if email in email_2_account: # 之前出现过，说明这个account属于之前的人
                    union(i, email_2_account[email])
                else:
                    email_2_account[email] = i

        groups = defaultdict(list)
        for email, account_idx in email_2_account.items():
            root = find(account_idx) # 需要找到最开始的user名合并在这里不然合并零散！
            groups[root].append(email)

        ans = []
        for root, emails in groups.items():
            name = accounts[root][0]
            ans.append([name] + sorted(emails))
        return ans

Reasoning: Nodes are account indices. A shared email is evidence for merging; identical names alone are not. email_2_account remembers the first account containing an email and merges accounts when it reappears, avoiding all-pairs comparisons. After all unions, collect and sort emails by find(account_idx).

If A contains x,y, B contains z, and C contains y,z, C joins both groups. The email map still stores original account indices, so roots must be looked up again when grouping.

The original comment about the “first user” means the current representative, not necessarily the earliest account. Accounts belonging to one person share a name, so accounts[root][0] retrieves it. An intersection-based approach must compare only accounts[i][1:], excluding names as evidence.

Review checkpoints

  • Merge roots, and leave the component count unchanged if they match.
  • Use find for membership and grouping. To count roots, test parents[i] == i directly.
  • Path compression updates only the visited path; later unions may change the representative.
  • This compact template uses path compression without union by rank or size. Do not apply the near-constant amortized bound associated with both optimizations. One recursive lookup on an uncompressed long chain may still visit many nodes.

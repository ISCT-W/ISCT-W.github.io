A sorting recap after a coding test: six Python implementations

A coding test reminded me how much sorting code I had forgotten. A short recap of bubble, insertion, quick, merge, selection, and counting sort.

WJunhao WeiAbout 3 min read

These sorting algorithms came up in a coding test, and I realized I had forgotten quite a bit. I put the six Python implementations together here, with a short reminder of what each one does.

Bubble sort

def bubble_sort(nums):
    n = len(nums)
    for i in range(n):
        for j in range(n - 1 - i):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
    return nums

Swap adjacent elements whenever they are out of order. Each pass moves the largest remaining element to the right, so the inner loop stops at n - 1 - i; without an early exit, this implementation always takes O(n2)O(n^2)O(n2) time.

Insertion sort

def insertion_sort(nums):
    for i in range(1, len(nums)):
        x = nums[i]
        j = i - 1
        while j >= 0 and nums[j] > x:
            nums[j + 1] = nums[j]
            j -= 1
        nums[j + 1] = x
    return nums

Treat the left side as sorted. Save the current element as x, shift larger elements one position right, and insert x into the gap; the worst case is O(n2)O(n^2)O(n2), while an already sorted array takes O(n)O(n)O(n).

Quicksort

def quick_sort(nums):
    if len(nums) <= 1:
        return nums

    pivot = nums[len(nums) // 2]
    left = [x for x in nums if x < pivot]
    mid = [x for x in nums if x == pivot]
    right = [x for x in nums if x > pivot]

    return quick_sort(left) + mid + quick_sort(right)

Choose the element at the middle index as the pivot, split the values into less-than, equal-to, and greater-than groups, then recursively sort the outer groups. Average time is O(nlog⁡n)O(n\log n)O(nlogn) and worst-case time is O(n2)O(n^2)O(n2): the middle index does not guarantee the median, and this version creates new lists rather than sorting in place.

Merge sort

def merge_sort(nums):
    if len(nums) <= 1:
        return nums

    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])

    res = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            res.append(left[i])
            i += 1
        else:
            res.append(right[j])
            j += 1

    return res + left[i:] + right[j:]

Split the array into halves, sort each half recursively, and merge them with two pointers. Time is O(nlog⁡n)O(n\log n)O(nlogn); <= takes equal elements from the left first, and the final return appends whichever side still has elements.

Selection sort

def selection_sort(nums):
    n = len(nums)

    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):
            if nums[j] < nums[min_idx]:
                min_idx = j
        nums[i], nums[min_idx] = nums[min_idx], nums[i]

    return nums

Find the minimum in the unsorted suffix and swap it into position i. Unlike bubble sort, each pass finds the minimum before making a single swap; this implementation takes O(n2)O(n^2)O(n2) time.

Counting sort

def counting_sort(nums):
    if not nums:
        return nums

    mn, mx = min(nums), max(nums)
    count = [0] * (mx - mn + 1)

    for x in nums:
        count[x - mn] += 1

    res = []
    for i, c in enumerate(count):
        res.extend([i + mn] * c)

    return res

Count the occurrences of each integer, then reconstruct the array in increasing order. The index x - mn supports negative integers too; with value range k=max⁡(nums)−min⁡(nums)+1k = \max(nums)-\min(nums)+1k=max(nums)−min(nums)+1, time is O(n+k)O(n+k)O(n+k), but a wide range makes the count array expensive in memory.

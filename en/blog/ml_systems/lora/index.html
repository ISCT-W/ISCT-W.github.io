LoRA: Low-Rank Updates, Quantized Bases, and Adaptive Budgets

Parameter-efficient fine-tuning restricts adaptation to a smaller trainable space, reducing gradients, optimizer state, and task-specific weight storage.

WJunhao WeiAbout 6 min read

Parameter-efficient fine-tuning restricts adaptation to a smaller trainable space, reducing gradients, optimizer state, and task-specific weight storage. LoRA, QLoRA, and AdaLoRA address low-rank updates, base-weight quantization, and rank allocation respectively. Their savings differ and must be assessed alongside activation memory, target modules, and task quality.

The frozen base and low-rank branch both contribute to the output, but only adapter parameters are updated. Freezing weights does not remove computation through the base or make activation memory disappear.

Restrict the update to a low-rank matrix

LoRA freezes base weights WWW and parameterizes the update as:

W′=W+ΔW,ΔW=αrBAW'=W+\Delta W, \qquad \Delta W=\frac{\alpha}{r}BAW′=W+ΔW,ΔW=rα​BA

Here A∈Rr×dinA\in\mathbb R^{r\times d_{in}}A∈Rr×din​, B∈Rdout×rB\in\mathbb R^{d_{out}\times r}B∈Rdout​×r, and r≪din,doutr\ll d_{in},d_{out}r≪din​,dout​. Training only A/B reduces trainable storage, gradients, and optimizer state.

Initialize with a zero update

Original LoRA initializes AAA with Gaussian noise and B=0B=0B=0, giving:

ΔW0=αrB0A0=0,h0=(W+ΔW0)x=Wx.\Delta W_0=\frac{\alpha}{r}B_0A_0=0, \qquad h_0=(W+\Delta W_0)x=Wx.ΔW0​=rα​B0​A0​=0,h0​=(W+ΔW0​)x=Wx.

The newly inserted adapter initially preserves the pretrained output, while random A0A_0A0​ provides nonzero directions for learning BBB.

For upstream gradient g=∂L/∂hg=\partial\mathcal L/\partial hg=∂L/∂h, omitting the batch dimension:

∂L∂B=αrg(Ax)⊤,∂L∂A=αrB⊤gx⊤.\frac{\partial\mathcal L}{\partial B} =\frac{\alpha}{r}g(Ax)^\top, \qquad \frac{\partial\mathcal L}{\partial A} =\frac{\alpha}{r}B^\top gx^\top.∂B∂L​=rα​g(Ax)⊤,∂A∂L​=rα​B⊤gx⊤.

With random A0A_0A0​ and zero B0B_0B0​, BBB usually gets a nonzero first-step gradient while AAA initially gets zero. Once BBB moves, both can learn. If both factors start at zero, both gradients vanish and the branch cannot start learning.

One random factor and one zero factor preserve the initial function while allowing learning. Two zero factors preserve it but block learning.

Frameworks may use Kaiming or uniform initialization instead of Gaussian initialization. What matters is initially BA=0BA=0BA=0 without eliminating both gradient paths.

Target modules determine what can change

LoRA can attach to linear weights. Common choices are:

Target module Intuition Typical use
q_proj, v_proj Q changes where to attend; V changes retrieved content Original LoRA and small-budget configurations
q_proj, k_proj, v_proj, o_proj Adapt matching, content, and output mixing Broader attention adaptation
MLP gate_proj, up_proj, down_proj Adapt per-token nonlinear features Domain or capability adaptation; closer to full fine-tuning
Embedding, lm_head Change input token representations or output distributions New tokens or a genuine need to modify vocabulary/output layers

With limited budgets, start by testing Q/V or all attention projections. Quality-oriented configurations often use QLoRA-style all-linear, covering attention and MLP layers. Wider coverage increases trainable parameters, optimizer state, and adapter size, so decide through task evaluation.

The reason is not that attention “stores more knowledge.” Attention routes and mixes context-dependent information; FFNs perform per-token nonlinear transformations and have also been interpreted as key–value memories. Knowledge is distributed. Attention-only LoRA changes interactions with relatively few parameters, while adding MLPs provides more capacity for larger domain shifts.

Start with attention for small budgets, test all-linear for stronger adaptation, and consider embeddings or lm_head when the vocabulary requires it.

QLoRA: higher-precision adapters on a quantized base

QLoRA stores frozen base weights in 4-bit form while typically training A/B in BF16 or FP16:

h=Dequant⁡(W4bit)x+αrBAx.h=\operatorname{Dequant}(W_{4\mathrm{bit}})x +\frac{\alpha}{r}BAx.h=Dequant(W4bit​)x+rα​BAx.

Quantized blocks are dequantized to the compute dtype for multiplication. Gradients pass through the computation to LoRA without updating the frozen 4-bit base. This is neither full-model training with 4-bit gradients nor necessarily 4-bit adapter parameters.

Original QLoRA combines:

  • NF4, a 4-bit type designed for approximately normally distributed pretrained weights, often better suited than uniform INT4;
  • Double quantization, compressing scales/constants to reduce quantization metadata;
  • Paged optimizers, using paging/unified memory to mitigate temporary memory spikes and OOM risk in long-sequence training.
Aspect LoRA QLoRA
Typical frozen-weight storage FP16/BF16 4-bit, commonly NF4
Trained parameters LoRA A/B LoRA A/B
Main saving Gradients and optimizer state Additional compression of base weights
Costs that remain Activations and forward/backward work Activations, forward/backward work, and dequantization

all-linear is a common targeting policy, not the definition of QLoRA. Deployment can retain a quantized base plus adapter or dequantize, merge, and requantize; the latter can introduce further error.

LoRA reduces trainable state. QLoRA also compresses the large frozen base from 16-bit to 4-bit storage, while activation memory remains.

AdaLoRA: allocate low-rank directions within a global budget

Standard LoRA usually assigns the same rank rrr to every target matrix. AdaLoRA dynamically gives important matrices more directions and prunes less important ones under a global budget.

Its SVD-like update is:

ΔW=PΛQ⊤,Λ=diag⁡(λ1,…,λr).\Delta W=P\Lambda Q^\top, \qquad \Lambda=\operatorname{diag}(\lambda_1,\ldots,\lambda_r).ΔW=PΛQ⊤,Λ=diag(λ1​,…,λr​).

Each (pi,λi,qi)(p_i,\lambda_i,q_i)(pi​,λi​,qi​) is a rank-one triplet. Training starts with a larger init_r, estimates importance from parameters and gradients, then periodically masks/prunes low-importance λi\lambda_iλi​ values toward the total target_r budget. The final phase fixes the allocation and continues fine-tuning. Orthogonal regularization reduces redundant directions and stabilizes the decomposition.

Method Main problem addressed
LoRA Represent updates with fixed low rank
QLoRA Compress frozen base weights to 4-bit
AdaLoRA Allocate rank adaptively among matrices

AdaLoRA reduces waste from uniform ranks under tight budgets, at the cost of importance tracking, pruning schedules, and regularization. It is sensitive to init_r, target_r, warmup, pruning intervals, and total steps. Combining it with QLoRA is conceptually possible, but the framework must support the required quantization, pruning, and saving workflow.

LoRA typically assigns equal rank budgets. AdaLoRA begins with more directions and reallocates capacity according to importance during training.

Training and deployment savings

  • Lower training memory, especially Adam's first- and second-moment state.
  • Small adapters for storing and switching tasks.
  • Merge ΔW into base weights before deployment to avoid an extra inference branch.
  • Keep adapters separate for dynamic tenant/task switching.

Boundaries of parameter, activation, and behavior savings

  • Forward and backward computation still traverses frozen base layers.
  • Fewer trainable parameters do not eliminate activation memory.
  • Too little rank limits capacity; higher ranks can have diminishing returns.
  • Target modules, α, dropout, initialization, and data quantity affect quality.
  • Concurrent adapter serving needs weight scheduling, batching, and caching.
  • Restricting parameter updates does not guarantee freedom from overfitting or forgetting.

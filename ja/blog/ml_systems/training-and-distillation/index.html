学習の安定性と蒸留：失敗の原因から対策を選ぶ

数値的な不安定性と能力転移の失敗は、どちらも指標の低下に見えますが、診断方法が異なります。

W韋 君豪読了目安 4 分

数値的な不安定性と能力転移の失敗は、どちらも指標の低下に見えますが、診断方法が異なります。前者ではバッチ、活性、勾配、最適化状態に戻り、後者では教師信号、生徒の容量、データの網羅性を調べます。ここでは安定性と蒸留を分け、層ごとの評価でつなげます。

図の構造を見る（原文）
flowchart TD
    A["训练出现 NaN、Inf 或 Loss Spike"] --> B["复现具体 step 与 batch"]
    B --> C["检查数据、激活与梯度"]
    C --> D["核对精度、优化器与分布式状态"]
    D --> E["逐项调整并回测"]
    T["教师输出、表示或生成样本"] --> S["学生蒸馏训练"]
    S --> V["任务、长尾、安全与鲁棒性评估"]
    V --> F["检查教师偏差与学生容量"]

数値異常では最初に壊れた計算や状態を探します。蒸留では生徒が何を学び、どの能力を失ったかを確認します。学習損失や平均点だけでは判断できません。

不安定性を層ごとに特定する

原因には残差経路の尺度、初期化、正規化位置、学習率、混合精度のオーバーフロー、異常データ、分散通信があります。NaN/Infや損失急増が最初に出る層とステップを特定してから、Norm、初期化、最適化、精度、データを確認します。

主な仕組み

  1. Pre-LNとPost-LN： Pre-LNはAttention/FFNの前で正規化し、残差の主経路を恒等写像に近く保つため、深い層へ勾配を伝えやすくします。Post-LNは表現特性が異なり、初期化やWarmupへの感度が高くなり得ます。
  2. 種類と位置は別の軸： RMSNormは二乗平均平方根でスケーリングするLayerNormの代替です。Pre-LN/Post-LNはサブ層の前後という配置であり、RMSNormとPre-LNは同義ではありません。
  3. 初期化と残差尺度： 大きい重みは層を重ねると活性分散を蓄積させます。深さ依存の初期化、残差分岐のスケーリング、DeepNormなどを検討します。
  4. 学習率と最適化： Warmupは初期の最適化状態と表現を徐々に整えます。最大学習率、Adamのβ/ε、重み減衰、勾配クリッピングも影響します。
  5. 数値精度： FP16は指数範囲が狭く、あふれやすい形式です。BF16は通常より安定ですが仮数が短くなります。loss scale、勾配ノルム、活性最大値、非有限値を監視します。
  6. データと分散処理： 極端な長さやトークン分布、誤ラベル、重複・汚染、All-ReduceやCheckpoint復元の誤りも損失急増として現れます。

調べる順序

复现具体 step
→ 检查 batch/token/label
→ 记录各层 activation 与 gradient norm
→ 检查 AMP scale、NaN/Inf 和 optimizer state
→ 降低学习率并验证 gradient clipping
→ 对比单卡/小模型/FP32 基线
→ 再排查并行通信与恢复逻辑

教師信号から生徒モデルへ

蒸留では硬いラベルだけでなく、教師の出力分布、中間表現、生成結果を学びます。Soft targetにはクラスやトークン間の相対関係があり、大モデルの能力を小モデルへ移す手掛かりになります。

主な形式

  1. Logit Distillation
LKD=T2 DKL(softmax⁡(zt/T)∥softmax⁡(zs/T))\mathcal L_{KD}=T^2\,D_{KL} \left( \operatorname{softmax}(z_t/T) \Vert \operatorname{softmax}(z_s/T) \right)LKD​=T2DKL​(softmax(zt​/T)∥softmax(zs​/T))

温度 TTT を上げると分布が滑らかになり、最大以外のクラス同士の関係も学びやすくなります。

  1. Feature Distillation： Attention map、隠れ状態、特定の中間層を整合させます。
  2. Sequence-level Distillation： 教師の回答や推論系列をSFTで学びます。LLMでは合成データによる蒸留がよく使われます。
  3. Preference/Behavior Distillation： 文体、回答拒否、安全性、ツール選択などの振る舞いを学びます。

リスクと評価

  • 教師の偏りやハルシネーションもデータへ入る。
  • 生徒の容量が足りないと、長い裾の能力から失われ得る。
  • 合成データの多様性不足はモード崩壊を招き得る。
  • 平均Benchmarkだけでは安全性、校正、頑健性の低下を見逃す。
  • 非公開モデルを教師に使う場合は、出力の利用条件やデータの許可も確認する。

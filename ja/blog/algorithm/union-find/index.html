## 集合の代表元同士だけをつなぐ

W韋 君豪読了目安 10 分

集合の代表元同士だけをつなぐ

図の構造を見る（原文）
flowchart LR
 A["查询元素 a、b"] --> B["find(a)、find(b)"]
 B --> C{"根相同？"}
 C -->|是| D["已经连通，无需合并"]
 C -->|否| E["连接两个不同的根"]
 B --> F["查找时压缩路径"]

集合は根で表します。経路圧縮は所属を変えず検索経路を短くします。ここでは根を直接接続しています。サイズやランクによる併合は別の最適化であり、木が長い鎖に偏ることを防げます。

まず問題の構造を見極める

  • 同じグループか、何グループあるかだけが重要： 都市の間接的接続、変数の等値、共有メールアドレスなど、関係に推移性があります。
  • 集合を併合してから所属を調べる： 併合後に分裂しないため、根を代表元にできます。
  • 無向辺の追加による閉路判定： 既につながった二点を結ぶ辺を追加すると閉路になります。

ノードが何で、どの関係が併合を許すかを先に決めます。通常のUnion-Findは最短経路、有向到達可能性、辺の削除後の分裂を直接解きません。静的な連結成分ならDFSやBFSでも求められます。

状態設計と基本の骨格

  1. ノードに番号を付け、最初は自分を親とする独立集合にします。
  2. find(x) で親をたどって根を探します。掲載実装は経路圧縮も行います。
  3. union(x, y) で両根を調べ、異なる場合だけ併合し、同じなら False を返します。
  4. 問題に応じて成功した併合を数え、根を比較し、根ごとに分類します。

26 は小文字アルファベットの個数です。他の問題では実際のノード数に合わせ、1始まりの番号なら添字を一つ余分に確保します。

parents = [i for i in range(26)]
def find(x):
    if parents[x] != x:
        parents[x] = find(parents[x])
    return parents[x]
def union(x, y):
    px, py = find(x), find(y)
    if px == py: return False
    parents[py] = px
    return True

parents[x] は直接の親、find(x) は現在の根・代表元です。根は parents[root] == root を満たします。併合では二つの根をつなぎ、向きは選べます。代表元が最小番号や最初のノードである保証はありません。

なぜ len(set(parents)) では数えられないのか

所属は親ポインタの鎖全体で表されます。併合済みの同じ集合でも、直接の親は一致するとは限りません。 併合が未完了なのではなく、直接の親を代表元と取り違えていることが問題です。

union は一つの根の親だけを変更し、子孫全体を走査しません。find(x) は今回たどった経路だけを根に直結し、集合全体を更新するわけではありません。以前圧縮したノードでも、その後に根が併合されれば再度 find が必要になることがあります。

Number of Provincesの二重ループと同じ順序で例を追います。

操作 parents 意味
初期化 [0, 1, 2, 3] 四集合
union(0, 3) [0, 1, 2, 0] 3を0へ接続
union(1, 2) [0, 1, 1, 0] 2を1へ接続
union(2, 3) [1, 1, 1, 0] 根0を根1へ接続。ただし3はまだ0を直接指す
find(3) [1, 1, 1, 1] 3 → 0 → 1 をたどって圧縮

三回目の併合後は全ノードが連結済みですが、set(parents) == {0, 1} なので二集合と誤って数えてしまいます。

ノードが 0..n-1 の場合、正しい数え方は三通りあります。

# 方式一：对每个节点查当前根，再去重
count = len({find(i) for i in range(n)})

# 方式二：直接数根；不需要先压缩所有节点
count = sum(parents[i] == i for i in range(n))

# 方式三：初始化 count = n，每次 union 返回 True 时 count -= 1
# 见下面 547 的当前代码。

len(set(parents)) を使うなら、すべての併合後に全ノードへ find を呼び、数えるまで再併合しない必要があります。同じ集合かの判定も parents[x] == parents[y] ではなく find(x) == find(y) を使います。

例1：Number of Provinces

問題：LeetCode 547

私のコード

class Solution:
    def findCircleNum(self, isConnected: List[List[int]]) -> int:
        """
        并查集的经典骨架：
            parent = list(range(n))

            def find(x): # 一直往上找到parent是自己的节点！
                if parent[x] != x:
                    parent[x] = find(parent[x])
                return parent[x]

            def union(a, b): # 
                ra = find(a)
                rb = find(b)

                if ra == rb:
                    return False

                parent[rb] = ra
                return True
        """
        n = len(isConnected)
        provinces = n
        parents = [i for i in range(n)] # 记录各自的parent；初始化为自己

        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]

        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True

        for i in range(n):
            for j in range(i + 1, n):
                if isConnected[i][j] == 1:
                    if union(i, j):
                        provinces -= 1
        
        return provinces

考え方： 都市がノードで、行列中の 1 が併合の根拠です。対称行列なので上三角だけを見ます。異なる二集合を実際に併合したときだけ provinces を減らします。既に連結した二点では減らさないため、最後の全体圧縮は不要です。

[[1,0,0,1],[0,1,1,0],[0,1,1,1],[1,0,1,1]] で上の落とし穴を再現できます。正解は一つで、この個数管理は 1 を返しますが、親配列の重複除去では 2 になります。

例2：Redundant Connection

問題：LeetCode 684

私のコード

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        # 逻辑就是找到环，然后把成环的最后一条边删了吧？
        # 模拟一遍发现其实就是已经union的东西！
        parents = [i for i in range(len(edges) + 1)] # 从1开始！

        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = parents[px]
            return True

        for i, j in edges:
            if not union(i, j):
                return [i, j]

考え方： 入力順に無向辺を追加します。union(i, j) が False なら既に経路があり、その辺が閉路を閉じます。「木に一辺追加」という前提から、一意な閉路で最後に現れる辺であり、問題の返却順序を満たします。

[[1,2],[1,3],[2,3]] なら最初の二回が成功し、三辺目で [2,3] を返します。px は根なので、parents[px] は px と同じです。

例3：等式の充足可能性

問題：LeetCode 990

私のコード

class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        # 等于则连上，不等于则不连。判断所有不等的find是否到同一节点
        parents = [i for i in range(26)]
        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True

        non_equations = []
        for eq in equations:
            x, y = eq[0], eq[3]
            if eq[1] == '=':
                union(ord(x)-ord('a'), ord(y)-ord('a'))
            else:
                non_equations.append([x, y])
        
        for x, y in non_equations:
            if find(ord(x)-ord('a')) == find(ord(y)-ord('a')):
                return False
        return True

考え方： 文字をノードとし、すべての等式を併合してから、不等式の両辺が同じ根か調べます。不等関係に推移性はないため、!= を併合には使えません。

判定は全等式の処理後に行います。["a!=c", "a==b", "b==c"] の最初の式は一見問題なくても、後で a,b,c が同じ集合になるため、最終的には False です。

例4：Accounts Merge

問題：LeetCode 721

私のコード

from collections import defaultdict

class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        """
        思路：用set(a) & set(b) 非空则是同一个用户，直接union。 - 复杂度很高！
        """
        parents = [i for i in range(len(accounts))] # 每个人名对应在列表的index
        def find(x):
            if parents[x] != x:
                parents[x] = find(parents[x])
            return parents[x]
        def union(x, y):
            px, py = find(x), find(y)
            if px == py: return False
            parents[py] = px
            return True
        """
        更好的思路：直接遍历邮箱，第一次出现就放在当前index，不是则进行名字的union！
        """
        email_2_account = {}

        for i in range(len(parents)):
            for email in accounts[i][1:]:
                if email in email_2_account: # 之前出现过，说明这个account属于之前的人
                    union(i, email_2_account[email])
                else:
                    email_2_account[email] = i

        groups = defaultdict(list)
        for email, account_idx in email_2_account.items():
            root = find(account_idx) # 需要找到最开始的user名合并在这里不然合并零散！
            groups[root].append(email)

        ans = []
        for root, emails in groups.items():
            name = accounts[root][0]
            ans.append([name] + sorted(emails))
        return ans

考え方： ノードはアカウントの添字です。共有メールアドレスが併合の根拠で、同名だけでは不十分です。email_2_account は最初にそのメールを含んだアカウントを記録し、再出現時に併合して総当たり比較を避けます。全併合後、find(account_idx) ごとにメールを集めてソートします。

Aが x,y、Bが z、Cが y,z を持つなら、Cが二つの集合をつなぎます。対応表は元の添字のままなので、分類時に根を調べ直します。

原コメントの「最初のuser」は現在の代表元と読み、最古のアカウントとは限りません。同一人物の名前は一致するため accounts[root][0] で取得できます。集合の積集合を使う場合も、名前を証拠にせずメール部分 accounts[i][1:] だけを比較します。

復習の確認点

  • 根同士を併合し、同根なら集合数を変えません。
  • 所属判定・分類には find を使い、根の個数は parents[i] == i で数えられます。
  • 経路圧縮は訪問した経路だけを更新し、後の併合で代表元は変わり得ます。
  • このテンプレートは経路圧縮のみで、ランクやサイズによる併合はありません。両方を使う場合のほぼ定数の償却計算量を、そのまま当てはめないでください。未圧縮の長い鎖では、一回の再帰的な検索でも多くのノードをたどります。

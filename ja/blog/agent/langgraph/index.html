LangGraph：状態、復旧、長時間処理の実行規約

長い処理では次の関数を選ぶだけでなく、進捗保存、並行更新の統合、人の入力待ち、障害後に再実行できる操作の判断が必要です。

W韋 君豪読了目安 11 分

長い処理では次の関数を選ぶだけでなく、進捗保存、並行更新の統合、人の入力待ち、障害後に再実行できる操作の判断が必要です。LangGraph は状態と永続化でこれらを整理します。実行スナップショット、モデルの文脈、外部副作用を分け、再開を「停止した次の行から続く」と考えないことが重要です。

図の構造を見る（原文）
flowchart TD
    S["读取当前图状态"] --> N["激活节点执行"]
    N --> U["返回状态更新"]
    U --> R["按 Reducer 合并并行更新"]
    R --> C["保存 Checkpoint 与下一步信息"]
    C --> D{"继续、结束或等待人工输入"}
    D -->|"继续"| S
    D -->|"结束"| E["交付结果"]
    D -->|"等待输入"| H["相同 Thread 接收恢复值"]
    H --> P["恢复相关节点；保护可重放边界"]
    P --> N

保存するのは状態と実行進捗であり、任意のローカル変数ではありません。Interrupt の後は関連ノードを再実行するため、副作用を安全に再生できる境界が必要です。

本記事は 2026 年 8 月の公式 Python 文書に基づきます。永続化モードや Streaming は利用版で確認してください。

状態と更新の規約

State、Node、Edge の契約

State は共有スナップショットと Schema、Node はそれを読んで変更分を返す関数、Edge は次の実行先です。ノードは全状態を返す必要はありません。一時オブジェクト、接続、重複した大文書ではなく、必要な事実と制御項目を保存します。

コンパイルと実行設定

Compile は Builder を実行可能グラフにし、構造を検査して Checkpointer、Store、Breakpoint などを結び付けます。モデル学習や機械語への変換ではありません。通常はプロセス起動時に一度作り、要求ごとにグラフや DB 接続を再構築しません。

Schema の検証と負荷

TypedDict は軽量、Dataclass は既定値、Pydantic はより強い実行時検証・型変換を提供しますが負荷も増えます。性能と検証要件で選びます。ノード出力、ツール結果、古い Checkpoint には業務検証も必要で、型注釈だけでは不正データを防げません。

Reducer が統合の意味を決める

Reducer は既存値と更新値を統合します。指定しなければ通常は上書きで、リストなどには追加、重複除去、ID 更新を定義できます。決定性と順序依存を考え、同じ項目への並行更新に適切な統合規約を与えます。

メッセージには同一性と削除の扱いが必要

リスト連結だけでは ID による置換や削除を扱えません。メッセージ Reducer は復元、追加、置換、RemoveMessage などを扱います。Streaming の呼び出し、人の履歴修正、文脈圧縮ではこの違いが重要です。

経路、並行処理、終了条件

Conditional Edge と Command

Conditional Edge は独立した関数で経路を選び、Command は状態更新と goto を一緒に返します。純粋な経路選択は Edge、結果と更新が強く結び付く場合は Command が適します。全ノードが自由に跳ぶ設計は制御を見えにくくします。

Send と動的な展開

Send は実行時に下流タスクを増やし、Map-Reduce などに使います。展開数、並行数、Timeout、集約サイズを制限します。ユーザー入力による無制限な展開は資源と費用を使い尽くす原因になります。

Super-step の並行実行

Pregel に似た基盤では、同じ Super-step 内の独立した有効タスクを実行し、更新を統合して次を選びます。二本の辺がコード順の直列実行を意味するわけではありません。暗黙の依存や並行安全でない副作用を避けます。

書き込み競合と決定的な合流

異なる項目は別々に更新できますが、同じ項目には対応する Reducer が必要です。なければ競合エラーになり得ます。項目を分ける、適切な Reducer を定義する、ID 付き結果を Join Node で統合する、明示的に直列化する方法があります。

複数の予算でループを制限する

グラフのステップ・再帰上限、ツール回数、時間・Token・費用、同じ呼び出しの反復、無進捗、終了・失敗状態を管理します。上限では内部例外だけを返さず、説明可能な途中結果や人への引き継ぎを用意します。

実行履歴と記憶

Thread、Checkpoint、永続化部品

Checkpointer は保存と読込を担い、Thread は thread_id で識別する実行・会話です。Checkpoint は状態、次ノード、タスク、付随情報を含みます。同じ ID は同じ会話を継続し、新 ID は新状態を作ります。本番ではユーザー・Tenant の所有権も検証します。

実行スナップショットと会話横断データ

Checkpointer は短期記憶、復旧、人の介入、Time Travel に使う Thread 状態を保存し、Store は会話をまたぐ好みや事実を保存します。呼び出し済みツールは状態、回答言語の好みは Store が例です。長期情報には出典、更新時刻、権限、削除が必要です。

記憶のライフサイクル

短期記憶は永続化したメッセージや状態項目、長期記憶は User/Namespace 単位の Store から取得します。多いほど良いわけではなく、保存の価値、許可、機密性、範囲、期限、削除方針を確認します。

全履歴とモデルに見せる文脈

履歴を保存しても毎回すべてを入力する必要はありません。Token 数で切る、低価値の結果を除く、古い対話を要約する、長期事実を抽出する、履歴検索を使う方法があります。要約には欠落や誤りがあり得るので、監査記録、モデル文脈、長期記憶を分けます。

人の介入と障害復旧

停止と再開のプロトコル

interrupt(payload) は Checkpointer を通じて必要情報を保存し、直列化可能な内容を返します。人の入力後、同じ thread_id と Command(resume=value) で再呼び出しすると、その値が interrupt の戻り値になります。永続ストレージと安定 ID が前提です。承認には単なる同意ボタンではなく、操作概要、対象、引数を示します。

再開時のノード再実行と副作用

Interrupt を含むノードは先頭から再実行され、停止前のコードも再び動きます。メール、課金、DB 書き込みが重複し得ます。承認後へ移すか、永続 Task と冪等キー・一意制約で守ります。ローカル変数が中断したスタックとして残るとは考えません。

永続実行には冪等な境界が必要

保存進捗から再開するには、非決定的な呼び出しと副作用を永続化できる Task/Node 境界へ置きます。開始済みで完了未確認のタスクは再実行され得るため、書き込み、支払い、送信には冪等キー、状態確認、トランザクショナル Outbox などが必要です。

並行段階の Pending Writes

一つの並行ノードが失敗しても、成功した兄弟の更新を Pending Writes として保存し、復旧時は失敗部分だけを再試行できます。ただし状態更新の完了と外部要求の処理完了は別であり、外部の冪等性は引き続き必要です。

Replay、Fork、状態更新

Replay は古い Checkpoint より後を再実行し、Fork はそこから状態を変えて新しい経路を作ります。update_state は履歴自体を書き換えず、新 Checkpoint を作ります。前段結果は通常再利用され、後段の LLM、API、Interrupt は再実行されて変わり得ます。Time Travel では外部副作用を隔離するか冪等にします。

サブグラフの状態境界

カプセル化と永続化モード

Subgraph は再利用処理や Specialist をまとめます。参照文書では None は呼び出し単位で親の能力を継承し、True は Thread ごとの状態を保持、False は永続化を無効にして Interrupt や Durable Execution を使いません。不要な長期記憶は状態汚染や名前空間衝突を招くため、必要な箇所だけに与えます。

配信、観測、安全性

Streaming イベントと画面状態

updates は差分、values は全状態、messages は LLM の断片と情報、custom は業務進捗です。ほかに checkpoints、tasks、詳細な debug があり、前二者には Checkpointer が必要です。画面では Token、ツール状態、進捗を組み合わせ、内部思考過程ではなく公開可能な状況要約を配信します。

非同期、並行、Streaming の違い

非同期は I/O 待ちの間に別処理を進め、並行は実行時間の重なり、Streaming は結果の逐次配信です。組み合わせつつ、Semaphore、接続プール、提供元制限、キュー、Backpressure を設けます。切断時に処理を取り消すかも明示します。

エラー分類と局所復旧

一時的な通信・制限エラーはバックオフ、Schema・引数エラーは回数を限った修正、権限・業務規則エラーは再試行しない方針にします。未知障害は失敗状態か人の処理へ送ります。最小の安全単位で retry し、Timeout、原エラー、Trace を保持します。Fallback は能力互換を確認し、復旧前に副作用の発生を調べます。

Trace から層別評価へ

モデル呼び出し、Prompt 版、ツールと結果、ノード経路、Token、遅延、エラー、必要情報を記録します。機密を伏せ、Tenant 情報は公開ラベルではなくアクセス制御に使います。

最終正解だけでなく、ツールと引数、不要手順、RAG の召回・引用・根拠、構造化出力、人への適切な引き継ぎ、p50/p95 遅延、Token、費用、失敗、注入、越権、副作用を評価します。固定データで回帰を行い、運用 Trace と反応から新しい失敗を探します。LLM 判定器は人の例で校正し、唯一の正解にしません。

検索、ツール、状態の安全境界

文書の Prompt Injection、越権ツール、引数注入、Tenant 間漏えい、機密 Trace、危険な retry、SSRF、SQL 注入、パストラバーサルが主なリスクです。モデル出力を信頼せず、Allowlist と厳密 Schema、実行時再認可、読書き権限の分離、高リスク操作の承認、権限付きキャッシュキー、文書と指示の分離、SQL/Shell/URL の決定的検証を使います。

実装の実行規約を確かめる

確認する項目は次のとおりです。

  1. State の項目と Reducer の理由。
  2. Thread ID とユーザー・会話の結び付け。
  3. 保存先とプロセス再起動後の復旧。
  4. Interrupt 後に再実行するコードと冪等性。
  5. Tool の Schema、権限、Timeout、エラー。
  6. 並行分岐の統合と競合。
  7. 画面へ送るイベントと切断処理。
  8. ループ、Token、費用、並行数の上限。
  9. 誤った呼び出しを追える Trace。
  10. 公開前の回帰データと指標。

不具合では入力、失敗した段階、Prompt/Tool/State/Reducer/権限/モデルのどこが原因か、修正、再発防止例を具体的に残します。

次の境界が復旧と権限設計の基礎になります。

Tool Call ≠ Tool Execution
State ≠ Runtime Context ≠ Store
Checkpointer ≠ Long-term Store
Interrupt Resume ≠ 从断点下一行继续
可计算/可重试 ≠ 副作用可安全重放

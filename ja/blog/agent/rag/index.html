RAG：検索結果を検証できる回答につなげる

RAGは更新可能な外部知識をモデルに与えます。

W韋 君豪読了目安 10 分

RAGは更新可能な外部知識をモデルに与えます。しかし、文書を取り込んでから回答を届けるまでには、情報が歪む段階がいくつもあります。信頼性は検索の再現率や引用リンクの有無だけでは評価できません。知識源、コンテキストの構成、生成の制約、引用の検証を別々に設計し、失敗を具体的な段階まで追跡します。

図の構造を見る（原文）
flowchart TD
    D["文档接入、解析与版本"] --> I["结构感知分块与索引"]
    Q["用户问题"] --> P["权限与元数据范围"]
    P --> R["混合检索"]
    I --> R
    R --> K["重排与上下文压缩"]
    K --> E{"证据是否足以回答"}
    E -->|"是"| G["生成回答并逐项绑定来源"]
    G --> V["核对结论与引用的支持关系"]
    E -->|"否"| U["澄清、换工具或返回未知"]

検索は根拠の連鎖の一部です。図の確認点は、アクセスできるデータ、コンテキストへ入る根拠、最終的な主張を資料が支えるかをそれぞれ制約します。答えを含まない検索結果を、確定的な結論として扱ってはいけません。

ハルシネーションはどこから生じるか

LLMは条件付き分布に基づいて次のトークンを予測します。常に正しい事実データベースを照会しているわけではありません。知識不足、曖昧な指示、学習データの矛盾、長いコンテキストの利用不足、デコード方法などで、流暢でも根拠のない回答が生じます。対策は温度を下げるだけでなく、知識源、生成制約、検証、回答保留の四層で考えます。

原因の分類

  1. モデルの知識： 事実が未学習、古い、または情報源間で矛盾している。
  2. 入力： 前提が誤っている、指示対象が不明、利用可能な情報を超えている。
  3. 生成目標： とにかく回答するよう学習され、根拠不足で止まる振る舞いが弱い。
  4. コンテキスト利用： 根拠が長すぎる、位置が悪い、矛盾する、無関係な情報に埋もれる。
  5. デコード： ランダム性は出力の変動を増やすが、貪欲・低温でも同じ誤りを安定して生成し得る。
  6. ツールとデータ： 検索、OCR、データベース、APIが既に誤った結果を返している。

対策

  • RAG、データベース、業務ツールで更新可能な知識を渡す。
  • エンティティ候補を閉じた集合に制限し、構造化IDを使う。
  • 主張に引用を結び付け、根拠が実際に支えているか確認する。
  • 数字、日付、計算、権限に関わる事実には決定的なツールを使う。
  • Schemaや制約付きデコードで出力構造を制限する。
  • 検証器、self-consistency、別モデルによる確認を加える。
  • 根拠不足やツール失敗時には unknown を返すと定義する。
  • 検索品質と生成品質を分けて評価する。

温度を下げる主な効果はランダム性の低下です。CoTは多段階推論を助ける場合がありますが、いずれも事実性の保証にはなりません。

エンジニアリングへの応用

成功したツール結果から引用を作り、キャラクターや素材の候補集合を限定し、ルールデータベースや幾何検証を使う設計が考えられます。重要な事実を自由文生成から、決定的な根拠の手順へ移せます。

検索から引用までの失敗経路

RAGは外部情報を生成に加えますが、検索と生成の両方が失敗し得ます。適切な文書の検索漏れ、分割による条件の欠落、再順位付けの誤り、情報の矛盾、根拠の無視、答えがないのに回答することが原因になります。

失敗の連鎖

段階 典型的な失敗 診断指標
取り込み OCR誤り、表構造の欠落、旧版の混入 文書網羅率、解析精度
分割 条件と結論が分離、チャンクの大きさが不適切 答えを含むチャンクの検索可能性
検索 クエリ不一致、意味のずれ、権限フィルタ後に結果なし Recall@k、MRR、ゼロ件率
再順位付け 正しい文書の順位が下がる NDCG、Top-k命中率
コンテキスト 長すぎる、矛盾、中央の情報を見落とす Context precision、位置のアブレーション
生成 学習済み知識で根拠を上書き、誤った帰属 Faithfulness、groundedness
引用 リンクはあるが対応する主張を支えない Citation precision/recall

改善方法

  • クエリ書き換え、複数クエリ、メタデータフィルタ、ハイブリッド検索。
  • 親子構造、文の周辺窓、文書構造を考慮した分割。
  • Cross-encoderやLLMによる再順位付け。
  • 生成前にコンテキストが答えを含むか確認。
  • 主張単位の引用と含意の検証。
  • 矛盾時には資料と日時を示し、無理に統合しない。
  • 検索ゼロ件なら確認、別ツール、回答保留へ進む。
  • Webページや文書を信頼できない入力として扱い、プロンプトインジェクションに備える。

保守できるシステムとしてRAGを構成する

業務用RAGは、データ、検索、生成、権限、評価、運用を合わせたシステムです。基本の流れは次のとおりです。

数据接入与版本
→ 解析/OCR/清洗
→ 结构感知分块
→ Embedding + 关键词/结构化索引
→ 权限与元数据过滤
→ Query 理解/改写
→ Hybrid Retrieval
→ Rerank 与上下文压缩
→ 生成、引用与拒答
→ 评估、反馈和可观测性

各層の役割

データ層

  • 文書の所有者、テナント、版、有効日時、権限を保存する。
  • PDF、表、画像、コードに適した解析方法を選ぶ。
  • 重複を除きつつ、親子構造、章、ページ番号を残す。
  • 文書の更新・削除を索引にも反映する。

索引層

  • Dense Embeddingで意味の類似性を捉える。
  • BM25やキーワードで固有名詞、ID、完全一致表現を補う。
  • 構造化フィールドをメタデータフィルタに使う。
  • 規模に応じてHNSW、IVF、管理型ベクトルDBを選ぶ。
  • 埋め込みモデルの更新時には索引の版を管理する。

検索層

  • 質問の種類と時間範囲を特定する。
  • クエリの書き換え・分解、多段検索を行う。
  • ハイブリッド検索のスコアを統合する。
  • Cross-encoderやLLMで再順位付けする。
  • 重複除去、コンテキスト圧縮、トークン予算を管理する。

生成層

  • どのコンテキストに基づく回答か明確にする。
  • 各主張を情報源に結び付ける。
  • 根拠不足なら確認するか不明と返す。
  • ツール結果と文書本文の信頼度を区別する。
  • 後続プログラムに必要なら構造化出力を使う。

プラットフォーム層

  • テナント分離と文書単位のACLを実施する。
  • キャッシュキーにユーザー・プロジェクト・権限範囲を含める。
  • クエリ、検索、再順位付け、引用、トークン、遅延、エラーを記録する。
  • オフラインの正解集とオンラインのフィードバックで改善する。
  • 機微情報のマスキング、監査ログ、保持期間を定める。

根拠の品質とモデル規模の選択

正しい根拠が取れていれば、生成は抽出、要約、言い換え、構造化が中心となり、小型モデルで遅延や費用を抑えられる場合があります。ただし「小型ほど指示に従い、幻覚が少ない」は一般則ではありません。長さ、難易度、言語、指示追従、学習データに依存します。

小型言語モデルに向く場面

  • 固定Schemaによる抽出と分類。
  • 一文書・短いコンテキストの質問応答。
  • 高同時接続・低遅延の社内アシスタント。
  • エッジ配置や機微データのローカル推論。
  • 蒸留による特定タスクへの最適化。
  • 複雑な質問を強いモデルへ振り分けるルーターがある構成。

大型モデルが必要になり得る場面

  • 文書間の矛盾解消や横断的推論。
  • 多段検索、複雑な計画、ツール連携。
  • 長いコンテキストから細かな根拠を統合する処理。
  • 低資源言語や専門領域の理解。
  • 質の高い説明や自由度の高い文章作成。

評価方法

単問の正答率だけでなく、タスク成功率、引用の正確さ、回答保留率、TTFT/TPOT、リクエスト単価、最大同時接続、大型モデルへの引き継ぎ率を比較します。

推論計算の効果と事実性の限界

CoTは中間段階を生成し、算術、記号推論、計画に推論時の計算を増やします。一度のトークン遷移で結論を出す必要を減らす一方、出力トークン、遅延、誤りの伝播が増えます。生成された説明が、実際の意思決定過程を忠実に表すとも限りません。

より広い見方

  • Few-shot CoTは導出付きの例を与える。
  • Zero-shot CoTは段階的に考えるよう促す。
  • Self-consistencyは複数の推論経路から回答を投票で選ぶ。
  • 推論モデルは学習・推論の両方で長い内部推論を使う場合がある。
  • Agentのscratchpadは計画や観測を記録できるが、内部推論をすべて公開する必要はない。

製品では通常、隠れた推論の生データではなく、簡潔で検証できる理由や計算手順を示します。CoTを隠すだけで安全性は確保できません。不要な機微情報をモデルに渡さず、プロンプト、ツール、データを独立した権限で守る必要があります。

費用とリスク

  • トークンと遅延の増加。
  • 誤った中間段階に後続の回答が引きずられる。
  • もっともらしくても忠実でない推論文。
  • 単純な質問に強制するとノイズが増える。
  • 内部の機微情報が説明へコピーされることによる漏えい。
